## 1. Bottom line

The desk originates its own lines for the 13 unsettled Week 10 games from scoring data that was read off
the official standings page the same day, and it publishes every assumption those lines rest on. It does
**not** publish a pick, a price to beat, an ROI figure or a skill score, because the repository holds no
licensed market data — and it says so in the cell where that number would have gone.

Three things follow directly from that table, and they are the reason this pack is built the way it is.

**Home advantage is not a constant.** Home clubs are below .500 this season. The desk therefore defaults its
home-field assumption to **0 points** and publishes the line at 0 / 1.0 / 1.5 / 2.5 points, rather than
importing the ~2.5 points the 2025 season would have justified. Two of the 13 lines change favoured side
inside that grid, so the robustness gate fails — a model finding, not a data gap (see §4).

**Records-only strategies are refused, with a measurement attached.** Wins above points-based expectation in
2025 predict nothing about 2026 (r = -0.0077, p = 0.9675). The residual spread in wins is *smaller* than the
binomial noise floor around a points-based expectation (0.9862 versus 1.3616 wins in 2026), so at 8–10 games
there is no residual-skill signal to extract. "Remove luck" is implemented as an instrument, not a slogan.

**Dependence is priced, or bounded, never ignored.** Offence-versus-defence correlation is weak and its
interval spans zero (r = -0.2041, CI [−0.531, 0.136]). Same-game residual dependence — the coefficient a
parlay actually needs — cannot be computed from a season register, so those cells are **blank** and replaced by
Fréchet bounds. An unadjusted parlay at 0.50/0.50 prices at +300 under independence but the joint probability
can legitimately sit anywhere in [0.00, 0.50], which spans a fair price of +100 to unpriceable. Publishing the
independence number as if it were a price would be the single largest error available here.

## 2. What "verified" means in this pack

* **Per row, not per site.** Every published row carries the URL of the page actually read for it and the read
  date. The checker refuses a table row that has no source link, and refuses any cell that contains an
  abbreviation for "I don't know" — a blank cell with a hatch pattern means *no confirmed value exists*, which
  is a different claim from `n/a`.
* **Nothing inferred to fill a gap.** Market open/close, vig, implied probability, de-vigged probability, ROI,
  CLV, Brier and skill scores are empty in every register. They stay empty until a licensed feed exists.
* **Arithmetic re-derived at build time.** `data/nfl_desk/derived/` is generated by `src/nfl_desk/` from the
  input registers; `build_nfl_desk.py --check` fails if a committed page disagrees byte-for-byte with what the
  code produces. A page cannot drift from its own model.
* **League invariants asserted, not admired.** Points for must equal points against across the league, home +
  road splits must sum to games played, and each printed `win_pct` must equal the league's own convention
  (ties count half). Those asserts caught a real error in this pack: four `win_pct` cells had been computed as
  wins ÷ (wins + losses), which drops ties. They are corrected, documented as `FL-24`, and now guarded by the
  checker and by a unit test.
* **Sources state their boundary.** Each of the 14 source rows records what the page *does not* support — for
  example the standings page prints season totals, which is why the per-game margin standard deviation
  (`MF-20`) stays blank instead of being guessed at.

  recomputes it at every build.
* 3 game designations (Sam Darnold among them) are consistent with the claim but the club's Friday status column
  was not yet posted at read time; they are reported as pending, not confirmed.
* The peer standings register is a through-week-9 snapshot, so against today's read it is one game stale on
  exactly two clubs — New York Giants and Washington, who played Thursday night — across 17 cells, and its
  135-135 league invariant is now 136-136 (league average 22.9632 → 22.9599). Every such cell is labelled

  of error inside this pack's own registers).

Nine further findings come from the working tree itself (`repo-audit.html`), including three that were
re-computed rather than copied: the committed CSVs mix CRLF and LF line endings (a prior audit's count of 16
is stale), there is still no root `LICENSE` so reuse terms for the registers are undefined, the root landing

audit scripts are only reproducible in a **full** clone: `scripts/audit_repo.py` and `scripts/audit_sources.py`
diff against one hard-coded `BASE` commit, so a shallow clone (the default checkout depth) makes them crash
instead of reporting, and the generated `data/assurance/**` inventory they write silently goes stale. This pack
hit both halves of that — the clone was unshallowed so the inventory could be regenerated for CI, and while it
could not be, the scripts looked like a failing gate rather than a missing input.

## 4. The two failing gates, in plain words

* **`DG-05` Sample size — FAIL.** Zero settled selections exist. A strategy cannot be promoted on promise, so
  the performance board is empty and the reward ladder pays nothing. `MF-20` stays blank, which is also why
  the sample arithmetic is published as a grid rather than a single headline: with a margin SD of 10 points, an
  edge worth 1 point per game needs **125** settled games to clear a two-sided 5% test at 80% power; at 3
  points per game the same test needs 14.
* **`DG-12` Assumption robustness — FAIL.** Minnesota at Green Bay (+0.49) and Carolina at New Orleans (+0.69)
  flip favoured side when the home assumption moves by one point. A "signal" that is really a dial in the model
  is exactly what that gate exists to catch, so it is reported as a failure and flagged (`FL-17`), not smoothed
  over by picking a favourite value of home-field advantage.

Seven gates are `BLOCKED`, all by the same missing input family: `DG-03` licensed quote source, `DG-04`
point-in-time snapshots, then the gates that inherit from them (`DG-06` holdout, `DG-07` same-line CLV,
`DG-08` calibration, `DG-13` vig, `DG-15` decay). Each names the artefact that unlocks it.

## 5. Signals, competition and rewards

Twelve strategies are preregistered across the three structures the brief asked for: 7 single-bet structures,
2 parlay structures and 3 player-prop combo structures. Each row freezes a hypothesis, the inputs it needs, the
inputs that exist today, and the luck controls applied (points-based expectation instead of win-loss record,
push mass priced explicitly, key-number mass published, one family of twelve hypotheses with Holm–Bonferroni
controlled at α = 0.05).

The competition runs on **two boards**. Readiness — how much of a strategy's required input set is verified and
on disk — is ranked today: five entries sit at 1.00, two at 0.00. Performance — holdout ROI, same-line closing
value, Brier, a composite skill score — is blank for all twelve, and every entry is `TIER-0` with the reward
recorded as *"no reward on the performance board; readiness rank only"*. The four-tier ladder is published
before anyone competes, with its tie-break rule fixed (evidence gates, then readiness, then strategy id) so the
ranking cannot be nudged afterwards. Paying a reward for a promise would be the fastest way to make the whole
exercise worthless.

## 6. Injuries and depth

All 326 rows of the official Week 10 report for the 28 clubs playing that week were transcribed. 107 rows are
published individually (14 designated out, 11 questionable, 82 who did not practise); the remainder are
represented in per-club coverage counts rather than dropped, and the checker recomputes both from the raw read.
Those 107 rows become **77 club-unit deficiency records**, scored Out = 3, did not practise = 2, limited = 1 —
an ordinal screen with its weighting policy printed beside it, plus a cascading-cluster alert wherever two or
more players in the same unit group are impaired (19 groups, the deepest being Dallas' secondary at 8).

Two limits are stated rather than papered over. The report's `Injuries` column is blank on most rows, so
**body-part and therefore effect-size information does not exist** in this read (`FL-03`); and the report says
nothing about who the second string *is*, because the depth order a club actually plays is not on it (`FL-03`,
`Q-03`). The consequence is deliberate: the deficiency score is **not** converted into points of spread. A
prior pack publishes multiplier-style adjustments for absent starters; those weights are not calibrated against
anything measurable here, and converting an ordinal screen into a spread is how an unmeasured assumption ends up
inside a price.

## 7. Requirements, questions and suggestions

* **18 requirements** are tracked with the artefact that answers each one. 12 are satisfied, 4 partially, and 2
  are satisfied *as model rather than product* (own-line origination exists as reproducible code, not as a
  service). Nothing is marked satisfied because a page mentions it.
* **16 questions** each name the decision they gate and the discovery path that closes them. Nine are blocking:
  the data-rights answer (`Q-01`), point-in-time snapshots (`Q-02`), depth-string semantics (`Q-03`), active
  roster mechanics (`Q-04`), the market benchmark (`Q-07`), settled sample (`Q-08`), the dependence input
  (`Q-09`) and injury effect size (`Q-10`).
* **14 suggestions** for the site and the workflow are recorded with option paths, effort, reversibility, files
  touched and a recommendation — and **none is implemented**. Three touch files other sessions own (`SUG-01`
  root navigation, `SUG-02` a single canonical NFL section, `SUG-05` one standings register for the whole repo)
  and are logged as cross-scope requests rather than applied. `SUG-03`, a weekly four-anchor snapshot job,
  unlocks four gates and needs no licence and no money; `SUG-04`, a written rights decision, converts the
  project's largest invisible blocker into a scope choice.

## 8. What stays blank

24 items are on the flagged page, each with what cannot be confirmed, why it stays blank, and the artefact that
resolves it. None blocks the merge; all block the corresponding claim. The short version: no licensed quotes,
no vig or ROI or CLV; no archived snapshots, no proper time-series validation; no play-by-play, no same-game
dependence coefficient; no player ids, no resolved identity for three names; no 2026 rules page, so any claim
about 2026 rule changes is unverified (the featured-rules page still describes the 2025 changes).

## 9. Reproducing any number here

```bash
python3 scripts/build_nfl_desk.py            # regenerate 12 derived registers + 18 pages
python3 scripts/build_nfl_desk.py --check    # fail if the committed site differs byte-for-byte
python3 scripts/check_nfl_desk.py            # sourcing, invariants, table alignment, blank-cell discipline
python3 -m unittest tests.test_nfl_desk -v   # unit tests for pricing, model, correlation, depth, gates
python3 tools/run_tests.py                   # the whole repository's stdlib test suite
```

Every figure above is reproducible from those commands with no network access and no manual input. If a number
cannot be reproduced, the build fails — which is the only honest guarantee a register like this can offer.
