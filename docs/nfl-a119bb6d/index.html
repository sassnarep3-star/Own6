Official NFL Game Books, availability graph and snapshot ledger

The league publishes an official Game Book for every game it plays, linked from the league's own game centre. That one document carries the official starting eleven on both sides of the ball, the game-day Not Active list, the stadium, the 90-minute roof and surface designation, the game-day weather, the final score and the paid attendance. This pack reads it, hashes it, and turns it into the availability graph the model needs: who was expected to start, who actually did, and how deep the replacement was.

What this pack does not claim. The Game Book publishes no snap counts and no player-participation table — a keyword scan of the whole document finds 0 occurrences of “snap” and 0 of “participation”. The league publishes no club depth chart either (https://www.nfl.com/teams/<club>/roster/depth-chart/ returns the league's 404 page). So the depth of a replacement is published here as a lower bound counted from official Game Books alone, and the model must not pretend to know more.

What changed because of this pack

  • The requirement to use official NFL Game Books for actual starters and game-day status was recorded as blocked by earlier packs because no official source could be found. There is one.
  • The availability graph is no longer a plan: it is a dataset, with the expected starter taken from the same club's official Game Book of its previous game.
  • The designation “Questionable” is no longer a number somebody remembered. It is measured against the Game Book of the same week, with n and a 95% interval.
  • The injury-report hub is now captured with a clock time and a SHA-256 on every read, so a week-to-week change is a difference between two dated captures rather than a recollection.

Pages

  • Official Game Books — one row per game: venue, roof and surface, game-day weather, score, attendance, and the official link and hash of the document.
  • Availability graph — expected starter, actual starter, the replacement and the depth of the replacement.
  • Designation calibration — what each league designation meant in practice, with n and an interval.
  • Snapshot ledger — every official read with its URL, clock time and SHA-256.
  • Requirements — the requirements this pack moves, the gate that blocks each one and the number that would clear it.
  • Flagged for review — every irregularity and every cell the league does not publish.
