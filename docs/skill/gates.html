Validation gates SG01–SG12

Twelve fail-closed gates, and the crosswalk to the two older numbering schemes.

VALIDATION GATES

Twelve gates in three groups: three preconditions you must satisfy before you are allowed to look at results, six statistical tests that separate skill from luck, and three integrity requirements. Missing evidence is a fail, never a pass.

Why a third numbering scheme

The repository already carries two incompatible gate frameworks that reuse the same IDs: G1–G8 on the verified archive pages (where G1 is a Korean legal review) and G01–G10 in the empirical lab (where G01 is rights and market permission). Reusing either prefix would deepen a documentation defect that is already flagged. These gates therefore use SG, and the crosswalk below maps the same intent without pretending the frameworks are identical.

The ordering is not cosmetic

SG01–SG03 come first for a reason. If you do not hold the rights, cannot prove where each number came from, and did not freeze the plan before looking, then every statistic computed afterwards is uninterpretable — you cannot tell a real effect from the freedom you had in choosing what to measure. Computing the statistics first and asking about rights later is how projects end up with a confident number they cannot legally publish.

Fail-closed, concretely

  • A gate with no data returns false and a reason string. It never returns "n/a".
  • SG09 checks that the declared family size equals the number of p-values supplied, so a strategy cannot quietly declare "we only tried one".
  • SG03 compares the frozen plan hash with a recomputed hash. A changed threshold changes the hash and fails the run.
  • SG05 uses the strategy's own claimed edge to compute the required sample size. Claim a bigger edge and you must bring more evidence.
