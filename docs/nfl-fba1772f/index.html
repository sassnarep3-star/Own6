Executive decision brief · not a betting product

Build the evidence pipeline before the line engine

This review turns the repository’s NFL requirements into a decision order: permission and source policy first, then immutable point-in-time evidence, then prospective model tests. It does not supply odds, picks, injury assessments, or a claim of strategy skill.

Current recommendation: keep the leaderboard in research-only / no-qualified-strategy mode until data-use permission, market-data terms, a verified outcome source, frozen strategy registration, and prospective evaluation are all demonstrably in place. These are gates, not values to guess.

Decision readiness at a glance

OPEN · permission

Can this data be used for this purpose?

The repo has no documented license decision for gambling-use analytics or market data. See Q1–Q2.

OPEN · prices

Can we compare our price to a real market?

No verified executable, timestamped, same-line price archive is established in the core NFL register.

OPEN · outcomes

Can we test without leakage?

Require an official result provenance record, chronological splits, pre-registration, controls, and uncertainty.

NOT TRUSTED · availability

Can a reported injury identify a replacement?

No single report does. Join official status, dated roster/depth evidence, actual starters, inactives and playing time; retain conflicts.

Recommended implementation order

  1. Resolve data rights and market-data policy. Record the allowed source, use, storage/retention, redistribution boundary, quote timestamp semantics and settlement rules. Keep values blank until decided. Official context: NFL terms and NFL.com Terms and Conditions; neither link is itself a gambling-data license.
  2. Establish the immutable evidence ledger. Capture each permitted source with source URL, event/game key, observation clock, raw-content hash, parser version, schema checks, and correction/conflict history. Keep raw source material private until rights are resolved; expose derived analysis only.
  3. Start with one preregistered singles-only shadow model. Save each probability, model version, inputs known at prediction time, and cutoff timestamp before kickoff. Keep training, validation and final holdout seasons separate. Official schedule context: NFL schedule; it does not define the statistical validation method.
  4. Validate outcome and benchmark joins before ranking. Match game identity and settlement status to an official result record; price comparison requires a licensed executable quote on the same market/line and an explicit vig/void/push policy.
  5. Only then evaluate availability and more complex markets. Use injury changes as timestamped surprises, not static labels; use confirmed starters/inactives and playing time for replacement evidence. Admit parlays/prop combos only after direct joint-probability validation.
  6. Publish skill separately from staking. Lead with proper-score skill versus named baselines and uncertainty; display staking/realized return in a separate, gated panel. Make demotion-to-paper automatic and predeclared. A reward should be research priority, never a claim of guaranteed returns.
